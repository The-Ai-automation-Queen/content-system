1. Create Your Meta Developer App

This gives you access to Instagram’s API. You’ll create an app, add yourself as a test user, and generate a long-lived access token. Takes about 8 minutes.

1.1 — Create the App

1. Go to developers.facebook.com and log in with your Facebook account.
2. Click My Apps → Create App
3. Filter by ALL, then select Manage Messaging & content on Instagram → click Next
4. Select a business portfolio if you have one — if not, choose "I don’t want to connect a business portfolio yet" → click Next
5. No requirements needed — just click Next and then Create App

1.2 — Add Instagram Basic Display

1. In your app dashboard, find Instagram Basic Display → click Set Up
2. Scroll down and click Create New App
3. For all three URI fields, enter: https://localhost
4. Click Save Changes

1.3 — Add Yourself as a Test User

Don’t skip this. If you do, nothing will work and you’ll lose your mind figuring out why.

1. In the left sidebar: Roles → Roles
2. Under Instagram Testers → Add Instagram Testers → search your username → send invite
3. On your phone: Instagram → Settings → Apps and Websites → Tester Invites → Accept

1.4 — Get your short-lived token

1. In your Meta app dashboard go to Instagram → API Setup with Instagram Login
2. Click Generate Access Token → log in and authorize → copy the token

1.5 — Get your App ID and App Secret

1. In your app dashboard go to Settings → Basic
2. Copy your App ID and click Show to reveal your App Secret — save both

1.6 — Verify token + get your User ID

Paste this URL in your browser — replace the placeholder with your short-lived token:

Browser URL

https://graph.instagram.com/v21.0/me?fields=id,username&access_token=YOUR_SHORT_TOKEN

Save the id and username values from the response.

1.7 — Get your long-lived token (60 days)

Paste this URL in your browser — replace the placeholder with your short-lived token:

Browser URL

https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=YOUR_SHORT_TOKEN

Save the access_token from the response. This is your long-lived token — it lasts 60 days.

1.8 — Test pulling your posts

Confirm everything is working — paste this in your browser:

Browser URL

https://graph.instagram.com/v21.0/me/media?fields=id,caption,media_type,timestamp,like_count,comments_count&access_token=YOUR_LONG_LIVED_TOKEN

You should see a JSON list of your recent posts. If you do, the API connection is working.

📋 Save all four values before moving on — you’ll need them in Step 2:

Credentials

IG_ACCESS_TOKEN=your_long_lived_token
IG_USER_ID=your_id_from_step_1.6
IG_APP_ID=your_app_id_from_step_1.5
IG_APP_SECRET=your_app_secret_from_step_1.5

Build the proxy server

This Node.js server sits between your browser and Instagram’s API — no npm packages needed.

📋 Prompt 2 — paste into Claude Code

Inside the ig-dashboard folder, create a Node.js file called proxy.js that:

- Serves static HTML files from the same directory on port 3001
- Loads IG_ACCESS_TOKEN and IG_USER_ID from the .env file in the same folder
- Has a GET /api/ig/account endpoint that calls https://graph.instagram.com/me with fields: id, username, biography, followers_count, media_count, profile_picture_url
- Has a GET /api/ig/media endpoint that fetches the last 50 posts with fields: id, caption, media_type, timestamp, like_count, comments_count, media_url, thumbnail_url, permalink — then for each post fetches insights from /{id}/insights. For VIDEO posts use metrics: reach,saved,views,shares,total_interactions,ig_reels_avg_watch_time,ig_reels_video_view_total_time. For IMAGE and CAROUSEL_ALBUM posts use metrics: impressions,reach,saved,shares,total_interactions
- Uses only built-in Node.js modules — no npm installs
- Adds CORS headers to all responses

Why separate metrics by post type? Instagram’s API throws an error if you request video metrics on a photo post or vice versa. The prompt above already has the correct metric names for each type.

3. Build the Dashboard

One prompt. Claude Code writes the entire dashboard — all sections, all charts, all styling. Pure HTML, CSS, and JavaScript. No frameworks, no dependencies.

Paste the full prompt as-is — don’t break it up. Claude Code handles the whole thing in one shot.

📋 Prompt 3 — the full dashboard

Create a file called content-dashboard.html in the ig-dashboard folder. It fetches from http://localhost:3001/api/ig/account and http://localhost:3001/api/ig/media on load. Pure HTML, CSS, JavaScript — no external libraries.

Design system:
CSS variables: --bg #FFFFFF, --bg2 #FAF7F2, --bg3 #F2F4FF, --bg4 #E8EDFF, --accent #2C4BE0, --green #18794E, --blue #2C4BE0, --purple #6547A5, --text #24211D, --text2 #57534E, --text3 #78716C, --border rgba(36,33,29,0.16). Load Playfair Display, Source Serif 4, Inter and Space Mono from Google Fonts. Use Playfair Display for headings, Source Serif 4 for reading text, Inter for controls and Space Mono for compact labels. Use #FF5733 for heading accents.

Layout:
Sticky left sidebar (200px) + scrollable main content. Sidebar has a logo mark, section labels, nav links with active state (cobalt left border + cobalt text) driven by IntersectionObserver scroll-spy. Refresh Data button and last-updated timestamp at the bottom of the sidebar.

Engagement rate formula: (likes + comments + saves + shares) / reach x 100. Use reach for VIDEO posts, impressions for IMAGE/CAROUSEL as fallback. Color tiers: ≥5% green, ≥2% cobalt, below grey.

Section 1 — Profile bar (id="overview"):
Avatar image (or 📸 placeholder), @username in large bold, biography, then 3 stat blocks: Followers, Posts, Reach Rate (avgReach / followers x 100 shown as %).

Section 2 — Summary Stats:
6 stat cards in one row: Avg Likes (color #FF5733), Avg Comments (blue), Avg Reach (purple), Avg Saves (green), Avg Engagement Rate (cobalt, 2 decimal places), Total Reel Views. Each shows "per post" or relevant subtext.

Section 3 — Reel Watch Time (id="watchtime", only if VIDEO posts have ig_reels_avg_watch_time data):
4 cards with colored top borders: Avg Watch Time in seconds (purple) — ig_reels_avg_watch_time is in ms so divide by 1000, Total Watch Time in minutes (cobalt) — sum ig_reels_video_view_total_time / 60000, Total Views (green), Best Watch Time (blue) showing the reel with highest avg watch time and first 28 chars of its caption.

Section 4 — Algorithm Signals (id="signals"):
2 large cards side by side. Saves Rate: total saves / total reach x 100 in green, show "X total saves · Y% of likes become saves", note "Saves = strongest signal to the algorithm. Anything above 2% is solid." Shares Rate: total shares / total reach x 100 in blue, show total shares count, note "Shares push content beyond your audience. 1%+ on reach is strong."

Section 5 — Top & Bottom Performers (id="best"):
Two columns. Left: Top 3 (cobalt header). Right: Bottom 3 (grey header). Each row: rank number, thumbnail (or emoji placeholder), caption truncated to one line, time ago + post type below, like count and engagement rate on the right.

Section 6 — Engagement Over Time (id="timeline"):
Bar chart of the last 20 posts in chronological order. Each bar = likes + comments. Bar gradient from cobalt (#2C4BE0) at top to transparent at bottom. Show value above bar, date (M/D) below. Height proportional to max value, minimum 3px.

Section 7 — Best Time to Post (id="timing"):
Two side-by-side horizontal bar charts. Left: By Day of week — cobalt bars, best day highlighted green with bold label. Right: By Time bucket (6–9am, 9–12pm, 12–3pm, 3–6pm, 6–9pm, 9pm+, Late 0–5am) — blue bars, best time highlighted green. Each row shows avg engagement % and post count. Only show time buckets that have at least 1 post.

Section 8 — Hashtag Performance (id="hashtags", only if any hashtag used 2+ times):
Card with header row (Tag / Uses / Avg Eng / Avg Likes). Each hashtag row: tag name in blue, proportional bar, use count, avg engagement %, avg likes. Sorted by avg engagement descending. Max 12 tags.

Section 9 — All Posts Grid (id="allposts"):
Sort pills: Likes, Comments, Reach, Eng, Saves, Views, Recent. Grid of cards, auto-fill columns min 220px. Each card: thumbnail image (or emoji placeholder), post type badge (Reel=purple, Photo=blue, Carousel=orange), caption with 2-line clamp, 4 metric chips (Likes in #FF5733, Comments in blue, Reach in purple, 4th chip = Views in cobalt for VIDEO or Saves in green for IMAGE/CAROUSEL). For reels with watch time: show avg watch time and saves below metrics. Footer: engagement rate pill (colored by tier), time ago, link to open post on Instagram. Top 3 cards (after current sort) get a cobalt border. Clicking the card opens the post permalink in a new tab.

4. Token Auto-Refresh

Instagram tokens expire after 60 days. This step makes refresh fully automatic — set it once, forget it forever.

Don’t skip this. In 60 days your dashboard returns "Invalid OAuth 2.0 Access Token" and you have to regenerate everything. Takes 2 minutes now.

Build the refresh script

📋 Prompt 4 — token refresh script

Inside the ig-dashboard folder, create a Python script called refresh_token.py that:

- Reads IG_ACCESS_TOKEN from the .env file in the same directory
- Calls https://graph.instagram.com/refresh_access_token?grant_type=ig_refresh_token&access_token=CURRENT_TOKEN
- Gets the new token from the JSON response
- Overwrites the IG_ACCESS_TOKEN value in the .env file with the new token
- Logs each refresh with a timestamp to token_refresh.log in the same folder
- If the refresh fails: logs a FAILED entry AND sends a macOS desktop notification using osascript
- Uses only Python standard library — no pip installs

Set up the cron job

Find your Python path first:

Terminal

which python3

📋 Prompt 5 — cron job

Set up a cron job that runs refresh_token.py every 58 days at 9am. Use the absolute path to Python (from `which python3`) and the absolute path to the script. Verify the cron entry was created and show it to me.

Test it now

Terminal

python3 /absolute/path/to/ig-dashboard/refresh_token.py

You should see a timestamp log entry confirming the token was refreshed and .env was updated.

macOS cron permission issue: If cron can’t access your files, go to System Settings → Privacy & Security → Full Disk Access → add /usr/sbin/cron.

5. Run It

Start the server, open the browser, you’re live.

Terminal

cd ig-dashboard
node proxy.js

Then open this in your browser

http://localhost:3001/content-dashboard.html

Your dashboard is live with real Instagram data. Use the sidebar to navigate, click any post to open it on Instagram, and use the sort buttons to rank by any metric.

Common errors

Invalid OAuth 2.0 Access Token: Token expired. Run refresh_token.py manually.
does not support metric X: Don’t change the metrics in proxy.js — the ones in Prompt 2 are already correct for each post type.
Insights show "—" everywhere: Your account is Personal. Switch to Creator in Instagram Settings → Account.
Cron job not running: Add /usr/sbin/cron to System Settings → Privacy → Full Disk Access.
Port 3001 already in use: Run lsof -ti :3001 | xargs kill -9 then restart.
