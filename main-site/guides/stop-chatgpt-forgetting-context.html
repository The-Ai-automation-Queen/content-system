Why does ChatGPT forget what you told it?

Put the few facts that must stay the same in a Project. Test if a new chat uses them without another reminder.

IN THIS GUIDE01 · Choose chat or Project02 · See the sample brief03 · Build and test it

A new chat may not have the brief you gave in another conversation. A Project keeps related chats and instructions together. You still need to check what each answer actually used.

Choose where to work

One question or ongoing work?

Use a Project to keep related chats, files and instructions together.

One example you can try

Keep an event brief steady

Imagine you are planning a short online session. You need an event description today and an invitation next week. Both must use the same facts. Put those facts in one Project, then start a separate chat for each draft.

AudienceFirst-time managers.
FormatA 60-minute online session.
PromiseHelp them run a clearer weekly team meeting.
BoundaryDo not promise a recording. Mark missing details Not decided.

Use this invented event first. It lets you see if the second chat keeps the brief without you repeating it.

Start the setup

Create your test Project

Open ChatGPT ↗, select New project in the sidebar and name it Autumn event plan. You do not need to add a file or connect an app for this test.

Get the Project instruction

Get the complete Project brief, two test messages and a link back to this guide.

Finish the test

Add the brief, then try two chats

Follow the remaining steps in order. The Project instruction and both test messages are visible where you need them.

Step 2 / 4

Add the fixed facts

Open the Project’s menu, choose Project settings and paste the brief below into its instructions field.

Project facts
- The event is a 60-minute online session for first-time managers.
- The goal is to help them run a clearer weekly team meeting.
- The tone must be practical and calm.
- Do not promise a recording.

For every draft, separate confirmed facts from suggestions. If information is missing, label it “Not decided”.
Step 3 / 4

Draft the event description

Start a chat inside the Project and send the first test message. Check it against the Project brief.

Write an event description in 80 words or fewer. State who it is for, the format and what people will learn. Use only the confirmed Project facts. If a detail is missing, write ‘Not decided’ instead of guessing.
Step 4 / 4

Try a second Project chat

Start another new chat inside the same Project and ask for an invitation. Check that it keeps the audience, format, goal and recording boundary without you pasting the brief again.

Write a short invitation for the same event. Include who it is for, the format and what people will learn. Do not promise a recording or set a date. Use the Project facts without asking me to paste the brief again.

The second chat should use the Project brief without you pasting it again. If it misses a fact, confirm that both chats are in the same Project and that the instruction was saved in Project settings before relying on it.

Check the invitation: did the second chat keep the audience, format and goal without inventing a date or promising a recording?
