## Durable mechanics locked for the public guide

1. Start with 1 decision, not a chart. Name the person who will make it and what action the dashboard may support.
2. Use only approved data. Record the source, owner, date range, refresh date and fields that are allowed or prohibited.
3. Write a data dictionary before asking AI to build. For each field, state the common-human meaning, format, allowed values, empty-value rule, calculation and sensitivity.
4. Keep the untouched source export. Clean and transform a working copy so the result can be traced and rebuilt.
5. Ask for the smallest useful view. Every chart, number, filter and label must answer the named decision or explain why the result cannot be trusted.
6. Reconcile the dashboard with the source. Check row counts or record counts, totals, duplicates, missing values, dates, time zones, categories, filters and edge cases.
7. Inspect the output itself for customer or confidential data. Hidden labels, aggregated values and a self-contained file still need review before sharing.
8. Make missing, late or invalid data visible as Missing or Unknown. Never turn it into 0, Healthy or Complete without evidence.
9. Record exactly which version passed, who approved it and what changes require a rebuild or new approval.
10. Keep the business decision with the named owner. AI may prepare code, formulas, summaries and possible patterns. It does not approve data meaning or the final action.

## Critical claim corrections

### Local does not mean private by default

A local Codex workflow and a Codex cloud task are not the same environment. Even when file operations occur on the device, model requests and connected tools can have separate data paths. The public guide must require the reader to check the exact tool, workspace, data controls and organisation policy.

### Hidden is not removed

Removing a count from a label does not remove the value from the file. A self-contained HTML dashboard may embed records, coordinates, review snippets, calculated values or source text in its code. The final file must be inspected before sharing. If a viewer does not need the field, remove it from the output rather than hiding it with CSS or a tooltip rule.

### Aggregated does not always mean anonymous

A precise location, unusual purchase time, rare phrase or very small group can still point to a person or reveal confidential business information. Set a minimum group rule when needed and ask the business's privacy or data owner to approve the release.

### A polished chart can still be wrong

AI can write code that opens and looks complete while using the wrong column, date range, time zone, filter, unit or formula. Reconcile the displayed result with the approved source and test known cases before the dashboard supports a decision.

### A pattern is not a cause or a decision

The top hour in an order export does not prove the best message time. A frequent review word does not prove the best position. A location cluster does not prove where to spend. The dashboard shows recorded patterns under stated rules. The decision owner considers context, tests and consequences.

### Any platform is too broad

Exports differ in columns, dates, permissions, limits and quality. The method is tool-flexible because the contract is explicit, not because every file works without preparation.

## Locked 6-step method

### 1. Decide what the dashboard must help someone do

- Action: write 1 business question, 1 decision it may support, the decision owner, how often the decision occurs and what the dashboard must never decide or change.
- Finish line: the owner can complete this sentence: `I will use this dashboard to decide whether to ____.`

### 2. Approve the data boundary

- Action: name the source file or table, source owner, date range, approved account and people with access. Remove fields the decision does not need. Record prohibited fields and the rule for small groups or sensitive values.
- Finish line: the source owner and privacy or data owner approve the working copy before it reaches the AI tool.

### 3. Define every field and calculation

- Action: create the data dictionary. For each field, record what it means, source column, format, allowed values, empty-value rule, date or time zone, calculation, sensitivity and owner. Write the expected dashboard result and the checks that will prove it.
- Finish line: another person can calculate 1 dashboard result from the source without guessing what a field means.

### 4. Build the smallest useful view

- Action: give the approved tool the decision brief, data dictionary, working copy, visible fields, prohibited fields, calculations, output format and quality checks. Ask for only the charts, numbers, filters and notes needed for the decision. Keep the source untouched.
- Finish line: every item on the dashboard answers the business question, explains a limit or helps the owner inspect the evidence.

### 5. Test the numbers, privacy and use

- Action: compare the dashboard with the source calculation. Test missing, duplicate, invalid, zero, tied and unusually large values. Check dates, time zones, filters and empty states. Inspect the final file for prohibited customer or confidential data, outside links, network calls and embedded source records.
- Finish line: the test log shows the expected result, actual result, evidence and Pass or Fail for every required check. Any failure blocks use.

### 6. Sign off and set the rebuild rule

- Action: record the file version, source period, data owner, technical reviewer, decision owner and approval date. Write how to refresh the data, what must be retested and which changes require a full rebuild or new approval.
- Finish line: the decision owner chooses exactly 1 status: Use, Fix and retest or Do not use.

The dashboard is ready only when:

- exactly 1 business decision and 1 decision owner are named;

- the data owner, technical reviewer and decision owner have recorded approval;
- the refresh steps, retest list and rebuild triggers are written;
- the final status is Use.

Stop or ask the relevant owner when:

- the dashboard has no named decision or decision owner;
- the source cannot be reopened or the source owner is unknown;
- a field, calculation, unit, date range or time zone is unclear;
- the data contains names, contact details, addresses, payment information, private messages, credentials, health information or another sensitive field that is not approved for the tool and purpose;
- the business has not approved the account, retention, deletion, access or output-sharing rules;
- a small group, precise location or rare text could expose a person or confidential result;
- the dashboard total does not match the source calculation;
- a missing value is shown as 0, Healthy or Complete without evidence;
- the generated file contains an unapproved network call, outside dependency, script, formula, link or embedded record;
- customer language is turned into a public claim without permission, context and approval;
- the result would trigger an automatic customer, money, access, publishing, deletion or lasting action;
- a technical, privacy, legal, financial or other expert issue cannot be judged by the reader;
- a required test fails or approval is missing.
