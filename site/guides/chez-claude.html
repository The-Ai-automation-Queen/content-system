01

Decide if Claude fits your work

The useful answer comes first. The table below shows when Claude can carry the work and when you need a different system or stronger review.

Choose Claude

When the work needs depth and continuity

  • Read, compare or reorganize long documents.
  • Develop a complex draft through several rounds.
  • Keep instructions and reference material together in a project.
  • Inspect, explain or change code with repository context.
Do not delegate the final call

When an unchecked error would cause damage

  • A factual claim must be correct before publication.
  • Legal, medical, financial or safety judgment is required.
  • Sensitive information has not been approved for the tool.
  • The output must be identical and deterministic every time.

How Claude handles a task

This is the working system underneath the chat box. More context can improve the answer, but it also gives Claude more material to misunderstand.

01

Instruction

The outcome, audience, constraints and format you ask for.

02

Context

Files, prior messages, project knowledge and examples Claude can see.

03

Model

The Claude model interprets the task and generates its response.

04

Tools

Search, code execution, connectors or MCP can extend what it can access.

05

Output

Text, analysis, code, a file or an Artifact is produced.

06

Review

You verify claims, inspect changes and decide what is safe to use.

The review step is part of the workflow. Claude can accelerate judgment; it cannot own the consequences of that judgment.

04

What each Claude feature does

Ignore the product vocabulary until you know which job it solves. Start with the job, then choose the feature.

Conversation

Claude chat

Ask questions, upload files, draft, analyse and iterate in the web, desktop or mobile app.

Use it when: the work can happen in a conversation.

Persistent context

Projects

Keep instructions, chats and reference documents together around one body of work.

Use it when: the same context matters across sessions.

Visible output

Artifacts

Create a document, chart, interface or other editable output beside the conversation.

Use it when: you need to inspect and refine the result.

Software work

Claude Code

Work with files and repositories from a coding environment, including multi-file changes and tests.

Use it when: the task needs codebase context, not a pasted snippet.

External context

Connectors and MCP

Give Claude controlled access to tools, data and services outside the conversation.

Use it when: the answer depends on live business context.

Build your own

Claude API

Put Claude inside a product, workflow or agent system and control the surrounding logic.

Use it when: the work must run repeatedly or at scale.

05

What to check before you trust the output

These named risks are not edge cases. They are the review checklist for serious work.

Hallucination

Serving an answer without checking

Claude states an incorrect detail as fact. Open the source and verify claims and numbers.

Confabulation

Filling a gap with a plausible story

Claude invents an explanation instead of admitting that information is missing. Ask for sources, assumptions and gaps.

Sycophancy

Adding salt because the customer asks

Claude follows your framing because agreement appears helpful. Ask it for the strongest objection before deciding.

Prompt injection

Accepting a fake order ticket

Outside content contains instructions designed to redirect the system. Treat files and webpages as untrusted input.

Data leakage

Sending one table's information to another

Private information appears in the wrong context. Control access, separate data and check policy before uploading.

Bias

Treating customers differently without evidence

Patterns learned during training can produce unfair assumptions or uneven outcomes. Check who benefits and who is excluded.

Overconfidence

Calling the result safe without checking

Strong certainty hides weak evidence. Require sources, uncertainty and qualified human review for high-stakes work.
